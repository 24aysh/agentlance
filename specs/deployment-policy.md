# Deployment and objective validation policy v1

## Frozen economics and deployment facts

Hackathon v1 uses **native MON only**, 18 decimals, on Monad testnet. Root/child creation requires `msg.value == budgetAtoms`; all other commands require zero value. No ERC-20 adapter, token allowance, fee-on-transfer or currency oracle. Pure L1 arithmetic remains atomic-unit arithmetic. Mainnet is a new deployment review, not an environment flag that silently changes live funds.

A completed `DeploymentManifest` in the shared schema contains actual chain ID, market/registry/publisher addresses and runtime code hashes, deployment block/hash, registry implementation versions, validator address, RPC endpoints, and digest-bound verification reports. Do not check in a partially filled manifest or use synthetic fixture addresses as deployments. Current target is the [official Monad testnet](https://docs.monad.xyz/developer-essentials/testnet); query eth_chainId and genesis/network identity during deployment and verify against that published network. No concrete address or endpoint is claimed verified by L0.

Before publishing a manifest, verify: market policy immutability and code; registry ownerOf/getAgentWallet behavior, transfer clearing and contract-wallet authentication; feedback registry's identity binding and owner/operator publication restriction; publisher binding to this market/registry; validator key control; historical reads; finality RPC behavior. Record exact source revision and implementation/proxy addresses in the verification documents. If an external proxy can upgrade, record its admin/trust assumptions and halt new bids on unexpected code/implementation changes; existing settlement uses frozen obligations and must not need a fresh registry read. The [ERC-8004 draft](https://eips.ethereum.org/EIPS/eip-8004) is the interoperability target, not a guarantee about any unknown deployment.

V1 has one immutable operator-funded validator address and no rotation for old tasks. It signs as an EOA (including accounts with delegation code, provided the ECDSA key controls the address); contract-validator signatures are excluded. Loss/unavailability follows VALIDATOR_TIMEOUT. The validator does not allocate, edit task terms or choose payout. Distinct addresses cannot establish independent operators; this trust limit must be disclosed.

## Confirmation and fetching policy

Wait for `eth_getBlockByNumber("finalized",false)` and a successful transaction receipt whose canonical block hash matches a block at or below that finalized height. Then re-read task state before acceptance/execution. Require finalized acceptance before paid tools/models. RPC unsupported/stale/error means WAIT/ABSTAIN, never fallback to `latest` or an invented block count. Verify endpoint support before deployment. This is the selected client policy, not an assumed claim that every Monad RPC supports the tag. [Monad transaction lifecycle](https://docs.monad.xyz/developer-essentials/wallet-developers) and [Execution API block-tag definition](https://ethereum.github.io/execution-apis/api/methods/eth_getBlockByNumber/).

Poll at most every 2 seconds, each RPC attempt at most 10 seconds; retry until the relevant task deadline, then stop that action. Bidders must budget confirmation latency inside the immutable 120-second minimum acceptance window. URLs are discovery hints: deny private/link-local/loopback destinations and redirects to them, recheck DNS on connection, 10-second fetch timeout and at most 3 redirects, enforce byte bounds while streaming, verify content digest before parse. IPFS retrieval uses a configured public gateway and the same bounds. Local fixtures do not require a live gateway.

## structured-output-v1 evaluator contract

This is a specification, not a validator implementation. Task input, output schema and ValidationPolicy are exact immutable bytes committed before bidding. Output schema is the restricted JSON Schema vocabulary represented by `OutputShape`; type object has explicit properties, required lists every property once, and additionalProperties=false. Arrays are bounded; integers are exact JSON integers in the stated interval; strings count Unicode scalar values without normalization. Maximum schema depth 16, 32 fields per object, 64 array items, 4096 string code points; no `$ref`, regex, custom formats, remote resolution, code execution or arbitrary schema keywords. Every object field is required. Integer limits are within ±(2^53−1) for interchange. Schema bytes themselves are ≤64 KiB. Names are ASCII identifiers as specified by the shape schema.

ValidationPolicy v1 contains outputSchemaDigest, 1–32 ordered deterministic predicates, and fixed limits. `equalsInput` compares a result JSON Pointer with an input JSON Pointer. `equalsLiteral` compares a result JSON Pointer with its scalar literal. Pointers use RFC 6901 escaping; empty pointer denotes the whole document, `/0` indexes arrays (no leading zeros, `-` or negative indices). Missing pointer fails the predicate. Deep equality is type-sensitive (boolean is not integer), object order-insensitive, array order-sensitive, exact Unicode string and integer equality. No floating-point values anywhere in input/result/policy. No inferred “semantic similarity.” This intentionally supports verifiable structured transforms, not arbitrary claims of correct reasoning.

Input/result/evidence each ≤1 MiB, depth≤16, ≤10,000 total JSON nodes (containers and scalar values); reject duplicate keys, BOM, invalid UTF-8, invalid Unicode scalar values, nonfinite numbers and JSON non-integer number tokens. Output-shape validation precedes predicates; predicates run in list order and first failure is recorded. Empty predicate list is invalid policy. Output schema digest in policy must equal task outputSchema.digest. Policy digest in task is keccak256 of exact policy bytes. Policy URI itself is not hashed instead of content.

| Condition | Validator behavior |
|---|---|
| Correctly fetched input/schema/policy; result bytes match commitment, valid JSON/limits, shape and all predicates pass | Sign PASS with reproducible evidence |
| Result bytes match commitment but exceed limit or have invalid JSON / shape / predicate | Sign FAIL with RESULT_LIMIT / RESULT_INVALID_JSON / SCHEMA_MISMATCH / PREDICATE_FAILED |
| Input/schema/policy unavailable, malformed, digest mismatch, evaluator unsupported, or result bytes unavailable/digest mismatch | Do not sign; retry bounded by validationBy; validator timeout remains possible |

A transport failure cannot be called a worker's incorrect result. EvaluationEvidence binds ExecutionRef and all four content digests, evaluator version, verdict/reason and first failed predicate index (null unless PREDICATE_FAILED). Store exact evidence bytes and put their digest in the verdict. Runtime operational timeout/crash produces no verdict; never fabricate FAIL. Run in a bounded process (5 seconds CPU, 128 MiB); exceeding operational limits does not override the deterministic input/result limits. Validator keeps artifacts/evidence retrievable; inability to retrieve later is an availability limitation, not retroactive settlement reversal.

Family `structured-output-v1` identifies this fixed template/evaluator version. Tasks vary schema and predicates, so family probability is an aggregate success proxy, not a guarantee of equal task difficulty. A new evaluator/template semantics requires a new family/version. Global prior and reputation mechanism stay unchanged.
