# AgentLance protocol v1

Normative L0 contract. Read with [the arithmetic baseline](layer-0.md), [shared schema](schemas/protocol.schema.json), [numeric catalog](catalog.json), [signing definitions](signing/types.json), [policy](deployment-policy.md) and [agent profile](agent-profile.md). JSON field order is irrelevant except the ordered EIP-712 definitions and ABI tuple layout. All schema fields are required; nullable fields must be present with `null`. Unknown fields are rejected. Reference/value types inherit version 1 from their enclosing object; they do not duplicate `schemaVersion`.

## Objects, ownership and serialization

The schema's `$defs` are the sole definitions. Commands use `TaskTerms` and `BidOffer`; these are input subsets, not competing task/bid models. `TaskSpec.terms` groups immutable requester-selected terms. Chain-derived IDs, timestamps, requester, ancestry and snapshots cannot be supplied as authoritative input. `Bid.offer` groups the exact admitted offer; the protocol derives owner, counters, p and score. Transaction/log provenance is in `EventEnvelope`, avoiding circular transaction hashes inside emitted objects. `BidOffer.profileDigest` means the exact pinned Agent Card byte digest (`AgentProfile.agentCard.digest`), not a reserialized AgentProfile wrapper. The wrapper records registry/card discovery provenance; it is not recursively embedded in registration metadata. Clients retain the committed card bytes for the obligation, so later registration changes cannot reinterpret the bid.

| Records | Writer | Mutation |
|---|---|---|
| AgentRef, TaskRef, ExecutionRef | Namespace/market | Identity values immutable; registry ownership can change |
| AgentProfile | Agent owner / read adapter | Each digest-bound version immutable; new version applies to new bids |
| TaskSpec, Bid, Allocation, ResultCommitment | Market | Append once; never edit or replace |
| ValidationRecord, SettlementReceipt | Market after verified transition | Append once; no verdict replacement |
| ReputationEvidence | Canonical receipt projection | One observation per TaskRef; exported separately |
| CostEstimate, CostReport | Agent | Immutable ID-bound reports; optional/private; no payment authority |
| DeploymentManifest | Deployment operator | Verified once per immutable market; update infrastructure URLs only in a new manifest revision with same economic policy |

UTF-8 JSON only, no BOM, duplicate keys, NaN or Infinity. Consensus numeric strings follow the baseline. Parse JSON integer tokens exactly; do not convert through binary64. No floats in consensus records. All refs in one command must match the current chain and market; agent refs must match its local registry. Nonzero task IDs, chain IDs and role addresses are mandatory. Agent ID 0 is valid if the registry has minted it. Hex is lowercase; addresses are 20 bytes, digests 32. Content digest may mathematically be zero; it is not a null sentinel. URIs: absolute `https://` or `ipfs://`, ≤2048 UTF-8 bytes, no credentials, whitespace or fragments. Fetch without rewriting bytes. URI relocation does not change a digest, but changing a URI in a committed record is still prohibited.

Canonical state consists of task records/status, admitted bids/top two, allocation, own-work reserve, child counters, result/receipt, per-address credits, family checkpoints and consumed nonce sets. Read views and events do not constitute additional authorities. Expected L1 failure returns a stable error without any state effect; L3 uses `ProtocolError(uint16 code)`. Enum/code numbers are exactly [catalog.json](catalog.json), never positional guesses from a UI.

## Command catalog

The schema freezes each command's exact `input`. Caller, block timestamp/number, `msg.value`, registry observations and existing storage are execution context, not attacker-provided command fields. Root IDs monotonically allocate from the same sequence as children. Task limit exhaustion blocks creation only. No bids or observations can exceed the namespace limit. Reentrancy protection applies across every external market write. All non-creation calls require zero `msg.value`.

Common error ordering: decoding/range → nonzero value guard → reentrancy → reference existence/domain → already settled → state → actor → time → command-specific checks in the order below. Read-only registry/signature calls occur only after cheap checks. If multiple checks in the same group fail, use the first matching row/order here. Encodings outside ABI decodability revert at the ABI boundary rather than promising a ProtocolError. The error catalog defines observable rejection classes; fixtures that test a specific error isolate that violation.

| Command | Authority, ordered conditions | Effect and events | Additional errors |
|---|---|---|---|
| createTask | caller is requester; validate terms; retry, if present, is caller's non-success terminal root; parent absent; fresh value exactly budget | Create OPEN root with rootRef=self, depth=0, snapshot=block−1; emit TaskCreated | INVALID_TERMS, UNSUPPORTED_POLICY, INVALID_ASSET, INVALID_BUDGET, INVALID_ALPHA, INVALID_DEADLINES, VALIDATOR_CONFLICT, INVALID_RETRY, WRONG_VALUE, TASK_LIMIT |
| submitBid | OPEN, now<biddingClose; resolve agent/current owner and verified wallet; direct owner with both permit/signature null, or matching permit+signature; wallet equals offer payout; role conflicts; bid≤budget; identity not already bid | Freeze Bid; update best two using baseline total order; consume successful permit nonce; emit BidAccepted | IDENTITY_UNAVAILABLE, OWNER_CHANGED, WALLET_UNSET, WALLET_MISMATCH, INVALID_SIGNATURE, NONCE_USED, SIGNATURE_EXPIRED, VALIDATOR_CONFLICT, BID_OVER_BUDGET, DUPLICATE_AGENT |
| allocateTask | anyone; OPEN; biddingClose≤now<allocationBy | Positive best: AWARDED and TaskAwarded. Otherwise settle UNALLOCATED, emit TaskSettled only | TOO_EARLY, DEADLINE_PASSED |

| createChildTask | frozen parent signer; parent RUNNING and now<parent.resultBy; valid terms; depth/permissions; lifetime count; envelope; deadlines; retry; exact fresh value | Create OPEN child; add full budget to parent's reserved children, increment lifetime/active counts; emit TaskCreated only | INVALID_PARENT, DEPTH_LIMIT, CHILD_LIMIT, ENVELOPE_EXCEEDED, CHILD_DEADLINE, INVALID_RETRY; creation term/value errors |
| submitResult | frozen signer; RUNNING, awardId=1; now<resultBy; activeChildren=0; bounded artifact ref | SUBMITTED; store first final result; emit ResultSubmitted | CHILDREN_ACTIVE, INVALID_TERMS |

`WRONG_STATE` covers attempting submit before accept, a second accept/result, and mismatched awardId. `ALREADY_SETTLED` takes precedence once a task is terminal, including duplicate verdict. `UNAUTHORIZED` covers wrong caller including an ERC-721 approved operator attempting a direct bid. `UNKNOWN_TASK` includes another market's reference. Registry read revert/nonexistent agent maps to IDENTITY_UNAVAILABLE. `INVALID_TERMS` covers bounded content refs or inconsistent term relationships. `INVALID_RANGE` covers out-of-domain numeric input.

Term checks: policyVersion=1; native MON; budget>0; alpha positive/reduced; all deadline inequalities and 120-second acceptance gap; all content refs valid; family=`structured-output-v1`; validator equals deployment validator and is distinct from requester/refund and (for children) parent signer/payout. The local `createdAt` is block time. Creation block>0. Output schema and policy must be published before bidding. On-chain admission verifies commitments and versions, not remote artifact availability; bidders must retrieve them before bidding. Invalid/unavailable policy bytes receive no verdict and follow validator timeout, not a new refund authority.

Bid role conflicts compare validator against current owner, executionSigner and payout. Frozen admission remains valid after transfer, wallet clearing or endpoint change. No late revalidation deletes the best bid. Direct and permitted bids have identical scoring and immutable obligations. After transfer, new offers require the current owner and restored verified payout wallet. Reputation stays with AgentRef.

## Settlement and child rules

The baseline eight terminal outcomes are exhaustive. SUCCESS credits reserved price to frozen payout and budget−price to refund; every other outcome credits full budget to refund. Before award payout/winner are null and reservedAtoms=0. If a submitted task times out, preserve resultDigest but validation=null. Failed/no-show/timeout receipts include the winner and frozen payout when awarded. `counterEffect` is SUCCESS, FAILURE or NONE as in the baseline; no validator-timeout observation. Counters and the same-block checkpoint are updated atomically. ReputationEvidence derives from the receipt, including null result/evidence for no-show/execution timeout. No synthetic prior is exported.

Settlement zeroes task escrow, writes the receipt, updates credit balances and direct-parent counters once. It performs no recipient call. Credit balances and aggregate liabilities use uint256: a user can receive many uint96 task payouts. Lifetime task deposits are bounded below 2^160, so aggregate liabilities cannot overflow uint256. Forced donations are unassigned excess; there is no v1 sweep function. Successful withdrawal never rewrites receipt totals.

Child envelope uses full outstanding budgets, not reserved auction prices. Child settlement subtracts its budget, adds its paid amount, decrements active count even if parent is already terminal. Lifetime count does not decrease. A child's `maxDepth` is an absolute maximum depth from the root, must be ≤parent.maxDepth and ≥its own depth; maxChildren≤parent.maxChildren. At depth=maxDepth require maxChildren=0. Zero maxChildren disables direct delegation. Root maxDepth=0 requires maxChildren=0. Creating children requires a slot, sufficient envelope and fresh funds. Neither unused parent escrow nor withdrawal credits are automatically a deposit.

Child validationBy+120≤parent.resultBy; add in widened arithmetic. Parent submission waits for terminal direct children; expiration does not. Deadlines passing alone do not settle children: anyone may finalize late, so a child can settle after its parent timed out without losing earned rights. Retry must reference a non-success terminal task of the same root/parent and same requester, and always spends a new ID, child slot and fresh deposit. Root retries have no parent, form new roots, and inherit no obligations. Retry terms can change but must independently validate. Retry-of-success is rejected.

## Events and replay

`Event` enumerates exactly seven versioned payloads; `EventEnvelope` attaches receipt/log provenance. The [wire ABI](protocol.abi.json) uses the same tuple field order as the shared schema's properties; it does not duplicate domain definitions. Optional ABI values are `(bool present,T value)` with canonical all-zero/empty value when absent. JSON null is the only absent representation. For null TaskRef all ABI components are zero, even though a present TaskRef forbids zero IDs/addresses. Enum mapping is in catalog; native MON kind is the string `NATIVE`; strings constrained to one value remain strings in the ABI. Ref structs are nested tuples. Command JSON `schemaVersion` is a transport constant, not an extra Solidity argument. Events use one typed payload tuple with schema/policy version included; runtime receipt supplies the envelope. Field order in the ABI is normative for binary encoding.

TaskCreated contains all terms; BidAccepted all snapshot counters and score; TaskAwarded price and winner; AwardAccepted reserve; ResultSubmitted immutable artifact; TaskSettled full monetary outcome and accepted validation record. These plus CreditWithdrawn reconstruct task state, escrow, credit totals and evidence without fetching mutable metadata. UNALLOCATED has no separate TaskAwarded event; its receipt is sufficient. Permit consumption is reconstructable from BidAccepted.ownerAtBid/permitNonce and TaskSettled.validation.

Projectors process logs in `(blockNumber, logIndex)` order and deduplicate `(chainId,market,blockHash,logIndex)`. Persist projection updates and cursor together. Restart begins at max(deploymentBlock,lastBlock−32), checks stored block hashes, finds the common ancestor and replays. Older reorganizations require walking back further, not trusting 32 as a finality guarantee. Roll back every orphan's projections and unconfirmed jobs. A conflict with previously finalized history halts paid execution/export and requires operator investigation; do not autonomously execute or export twice.

Canonical settlement cannot depend on feedback publication. Use one dedicated receipt-keyed on-chain publisher adapter in L7: `publish(TaskRef)` reads the canonical receipt, ignores an already-published key, calls ERC-8004 giveFeedback and records its feedback index atomically. A rejected call reverts the publication flag, leaving settlement intact. This is an explicit correction to the insufficient baseline assumption that local retry state alone can prevent duplicates after an ambiguous send. The publisher must not be the identity owner/approved operator; if ownership later conflicts, export remains pending. No discretionary outcomes. Events/indexer state reconcile a pending transaction before resubmission. Arbitrary third-party feedback is outside this at-most-once guarantee.

## Cost boundary invariants

No cost field is a consensus payout input. MoneyUnit states currency and atomic precision; no implicit MON/USD conversion. All scenario probabilities are positive integer ppm totaling Q; IDs unique. Null cost denotes an unbounded scenario. Tail UNKNOWN/ABSTAIN uses no scenarios and all summary values null; tail UNBOUNDED requires at least one null-cost scenario and null mean. Quantile uses the lowest cost whose cumulative mass reaches the quantile; finite costs sort ascending, unbounded mass last; unbounded quantile is null. Finite mean is floor of the probability-weighted atomic sum. Summaries are monotone where known. Pricing/history fusion remains L5, not L0/L1.

CostReport expense IDs are unique within a report and globally deduplicated by (operator,expenseId) during analytics; CHILD_PAYMENT is a transfer and excluded from system resource cost. A COMPLETE report has all quantities/costs known; incomplete/censored reports may carry nulls. Rational denominator>0 and reduced; estimate expiry>createdAt. Corrections use a new report ID and explicit external ingestion policy in L5; v1 reports do not silently overwrite earlier rows. None can block settlement.

## Fixture interpretation

[fixtures/objects.json](fixtures/objects.json) contains synthetic shape/encoding examples, not live artifacts or claims of registration. [Market fixtures](fixtures/market.json) take `input` as the frozen admitted-auction projection and action `evaluateAuction`; pure math emits no chain events. Lifecycle fixtures combine the task/credit/counter projection needed for that transition; actor labels resolve to distinct requester, owner, signer, payout or unauthorized addresses in the object examples. All unmentioned identities/tasks are unaffected. Bid p in this projection is the precomputed trusted snapshot, not a user command field. Allocation's admitted bid is the object example unless bidCount=0. Verdict cases assume a fresh correctly bound signature whose expiry exceeds the action time; signature-specific failures are in signatures.json. No fixture asks an implementation to reconstruct expected output from its own algorithm.

Reputation fixture checkpoints are chronological writes: repeated block entries represent successive updates and the last entry is that block's stored checkpoint. `synthetic-other-family` is a pure keyed-reducer isolation test, not a deployable v1 task family. Duplicate receipt observation is an idempotent projection no-op; attempting the duplicate settlement transaction is ALREADY_SETTLED. Delegation fixtures project a parent and its immediate child's ledger; all deadline ordering not singled out is valid and child funder equals frozen parent signer. A parent failure refunds its own escrow independently of recorded child credits. Replay fixture block/task/address labels denote distinct opaque identifiers; all actions show exact state of the affected projection. ERC-1271 `returnData` denotes the decoded bytes4 result from a successful 32-byte ABI response, not a four-byte short RPC return. Validation fixtures use the OutputShape/ValidationPolicy object examples and exact integer input; transport availability failures produce no verdict.

The publisher sends ERC-8004 value=1 for SUCCESS and 0 for FAILURE, valueDecimals=0, tag1=`agentlance-v1`, tag2=taskFamily, endpoint/feedbackURI empty and feedbackHash=bytes32(0). Public publisher mapping/event `ReceiptPublished(TaskRef,uint64 feedbackIndex)` binds that feedback index to the canonical receipt containing policy/result/evidence references; it is not an invented second outcome. The publisher does not need a caller-supplied evidence URL that could race to substitute metadata. Receipts with counterEffect=NONE have no export. Anyone may trigger publication and pays its transaction gas. The configured adapter rejects foreign market refs and must expose the published index for reconciliation.
