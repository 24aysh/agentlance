# Typed signatures v1

[types.json](types.json) fixes primary-type field order and Solidity widths. All refs are flattened: domain.chainId/domain.verifyingContract bind TaskRef namespace; taskId binds the immutable task. identityRegistry/agentId bind a same-chain AgentRef. Reject any JSON reference whose namespace differs from domain before encoding. No nested EIP-712 structs or JSON hash is used. The two primary types separate operations. A bid has no award yet; award reference is implicitly 0. Verdict awardId must be 1. Schema/profile/mechanism versions are 1; EIP-712 domain version is the string `"1"`.

Domain fields in order: name/string=`AgentLance`, version/string=`1`, chainId/uint256, verifyingContract/address. Domain types have no salt or extensions. `types.json` is the exact encodeType source. Hash using EIP-712: typeHash=keccak256(UTF-8 encodeType); structHash=keccak256(encodeData); domainSeparator=hashStruct(EIP712Domain); digest=keccak256(0x1901 || domainSeparator || structHash). Use standard ABI 32-byte field encoding. No packed encoding of dynamic fields, SHA3-256 substitution or JSON serialization hashing. [EIP-712](https://eips.ethereum.org/EIPS/eip-712).

The baseline's proposed task-terms digest is deliberately removed from BidPermit: immutable TaskRef already uniquely commits all terms. No second encoding of TaskTerms needs to be invented or maintained. A signature from a different chain/market cannot bind the same TaskRef. Verdict enum is FAIL=0/PASS=1; any other value rejects. The evidence URI is a locator supplied by the relayer; its exact content digest is signed. Chain stores the first accepted URI without treating it as evidence correctness.

Nonce scope is `(market, signer, primaryType, nonce)`, a used-value set, not a global sequence. Unused nonces may be out of order. Bid nonce signer is permit.owner; verdict nonce signer is pinned validator. Consume only on successful admission/settlement. Native direct bids consume no permit nonce. Check `now < expiry`; equality is expired. Bid permit must also be before biddingClose and verdict before validationBy. No separate cancellation API; use short expiry. A permit never authorizes withdrawals, result submission, child spending or an arbitrary contract call.

At consumption, compare current owner to signed owner before signature verification. A transfer to a different owner invalidates the unconsumed permit. After admission, frozen signer/payout remain obligated regardless of transfer. Returning the NFT to the same owner does not create an ownership epoch: an unused, unexpired permit by that owner can become valid again. This explicit v1 limitation avoids inventing a registry transfer counter; one-bid-per-task and expiry still apply. Registry approved operators cannot impersonate the owner.

For an owner with deployed contract code, call ERC-1271 `isValidSignature(digest,signature)` via staticcall with a 50,000-gas cap and require the ABI-encoded bytes4 magic `0x1626ba7e`; revert/wrong magic/short return/out-of-gas rejects. No ECDSA fallback for that owner. For a code-free owner, require exactly 65 bytes, low-s, v=27/28, recovered address equals signed current owner. No personal-sign prefix, compact signatures, counterfactual ERC-6492 or fallback success. Contract signature bytes max 4096. [ERC-1271](https://eips.ethereum.org/EIPS/eip-1271).

Validator is a pinned EOA and uses the same strict ECDSA rule regardless of delegation code. Bid executionSigner may be an EOA or a contract able to call the market; a verified payment wallet alone does not authorize a bid. Bid offer and permit fields must match exactly, including profile/payout. Registry wallet must equal frozen payout at admission. Contract-wallet support is verified against actual registry behavior at deployment.

Golden vectors are in [signatures.json](../fixtures/signatures.json). Keys 1 and 2 are public synthetic test keys, never deploy/fund them. Positive vectors include domain, message, type hash, domain separator, struct hash, digest, signature and recovered signer. Python eth-account produces them once; ethers independently computes every hash and recovers the stored signature. Both checkers only read expected vectors. Negative mutation vectors retain the original signature: message/domain tampering changes recovered signer; used nonce/expired time/transferred owner are authorization rejections even though the cryptographic signer remains valid. Primary-type tampering retains fields under another type name and must fail. Smart-wallet return/magic behavior is captured as a conformance fixture, not falsely claimed tested against a deployed contract.
